# 专家与交流

知识准备依次完成范围、文献库、广度阅读卡、领域理解、选队、选中论文补读和专家审核。先按研究价值选论文，再补齐关键理解；全文读完不是入选前提。领域分析保留竞争解释，证据不足时写明未知。

核心团队是领域专家与可配置数量的论文专家，允许按缺口邀请临时专家。选队比较对研究问题有用的方法贡献与覆盖，不把数据集、校准或最新年份本身当作选中理由。

| 角色 | 责任 |
|---|---|
| 领域 / 论文 / 临时专家 | 理解方法、提案和修订、解释结果、写作；领域专家引导讨论和统稿 |
| 工程师 | 搭底座、实现、调试和消融 |
| 批评者 | 独立检查可检验性、协议、实现、结果解释与查新 |
| 评审团与 meta-review | 审稿，要求修改、补实验或降级主张 |

专家先独立提案，再读取真实交叉意见、修订与去重；实验回来后再诊断和进化。讨论不要求共识，主持身份不授予批准自己主张的权力。当前串行执行，不表示所有专家同时在线聊天。

专家保存方法理解、发现思路的证据化重构、迁移策略、代码映射和表达方式。作者未公开的发现历史保持未知；读代码、封装接口和实际复现是不同能力。知识可复用，但需重新判断用途，源码阅读也不等于部署了 MCP 服务。
