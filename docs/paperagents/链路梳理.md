# 我们的链路

`research.md` 说清研究什么、怎样才有效；`paperagents.toml` 说清模型、资源、预算和交付；手头材料放 `inputs/`。

1. 检索并读论文卡，形成领域理解，按问题选择方法论文；补读、构建和审核专家。
2. 工程师搭评测底座，批评者检查数据、协议和基线。
3. 专家独立提案，交流、修订与去重；批评者评估哪些值得且能够检验。
4. 实现和实验多个候选，专家解释成功和失败，查新、消融并进化。
5. 证据支持的主张进入论文；评审可要求改写、开发集补实验或降低结论。
6. 冻结方法和主张后才打开最终测试。结果只能如实报告或降低结论，不能回头调参。

领域专家引导和统稿，科学判定由独立批评者与评审完成。实现失败不是自动否定 idea，讨论通过也不证明 idea 有效。

整条链共享主张版本和证据，网页追溯输入、输出和变更。由人启动真实运行，再用产物判断设计是否有效。
