# 论文专家：理解、论证与策略

论文专家分三层建立知识：先忠实理解材料，再重建公开论证，最后提炼可迁移的操作。代码映射与方法工具作为另一条能力链保留，不能用“读懂方法”代替真实运行验证。

## 1. 论文理解

[understand-paper](../../skills/knowledge/understand-paper/SKILL.md) 借鉴 Paper2Agent 的按需导航、来源审查和材料打包思路。每份实际读入文件登记版本、SHA256 与路径，正文、附录、图表和数据表之间保持可追溯关系。不是只读摘要，也不是把 PDF 提取出的文本当作已经确认正确的原文。

| 理解维度 | 需要回答的问题 |
| --- | --- |
| 问题 | 研究对象、任务目标、已有工作的具体缺口是什么？ |
| 方法 | 输入如何变成输出？关键步骤、模块和设计选择各做什么？ |
| 形式化 | 符号、单位、维度、假设与推导条件是什么？定理声称了什么范围？ |
| 图表 | 坐标、分母、归一化、误差条、样本量与比较条件分别是什么？ |
| 证据 | 什么主张由什么实验、证明、消融或负面结果支持？还不能排除什么解释？ |
| 前提 | 哪些量可观测、哪些条件被固定、哪些假设只被采用而未检验？ |
| 限制 | 作者声明与系统识别的限制分别是什么？正文是否被附录限定？ |

理论、实证、方法及 benchmark 论文按实际内容分析。不含公式可以说明不适用，不能为了字段完整发明公式。读不清的图、缺失附录和未解矛盾须记录。阅读覆盖 complete 只指申报材料的覆盖；科学理解仍需独立审查。

参考：[Paper2Skill 转换与审查流程](https://github.com/jmiao24/Paper2Agent/blob/8c2d059165ef8cdcb70dbea76655b9c2b55b38e6/skills/paper2agent/paper2skill/SKILL.md)、[论文知识包导航实例](https://github.com/jmiao24/Paper2Agent/blob/8c2d059165ef8cdcb70dbea76655b9c2b55b38e6/skills/paper2agent/paper2agent-paper/SKILL.md)。当前没有引入其完整 PDF 转换器；读图、转录与语义判断依赖实际 worker 工具。

## 2. 研究思路提取

[trace-paper-ideas](../../skills/knowledge/trace-paper-ideas/SKILL.md) 输出有稳定节点 ID 和依赖边的论证图，按材料适用性检查以下问题，而不是机械填满固定十步：

1. 什么观察、矛盾或目标差距触发了研究问题？
2. 最接近的方法具体卡在哪里？瓶颈有证据，还是作者提出的解释？
3. 原方法依赖什么显式或隐含前提？作者改变了哪个？
4. 核心洞察是什么，增加了哪些假设？
5. 为什么选择这个机制？替代方案被比较、排除，还是没有讨论？
6. 洞察如何落实为公式、算法或实验操作？推导有没有跳步？
7. 若机制成立，应观察到什么；竞争解释会预测什么？
8. 实际证据支持哪一步，哪些机制解释仍未被区分？
9. 在什么边界、反例或条件变化下论证会失效？
10. 作者的真实发现历史有哪些公开证据，哪些必须保持未知？

每个节点保存陈述、来源类型、引用、依赖、思维操作、前提、替代解释与可检验含义。作者明确论证、系统重建和未知历史分开；依赖图不代表作者实际尝试的时间顺序。未知节点仍可有作用，它明确指出当前不能补齐的推理。

## 3. 可迁移思维策略

[distill-reasoning-patterns](../../skills/knowledge/distill-reasoning-patterns/SKILL.md) 从论证图提炼可尝试的操作。例如“把总体误差拆成条件误差，检验某个条件是否解释表面差异”，而不是仅存“分解问题”四个字。

策略卡包括：触发的问题、变换前的表述、具体操作、变换后的问题/预测、应保留的关系、成立前提、失败与反例、来源节点、证据状态及迁移检验计划。八类操作提示见[详细协议](../../skills/references/reasoning-patterns-protocol.md)，包括换表示、边界检验、前提挑战、瓶颈分解、目标改写、机制类比、反事实干预和互补机制组合。

迁移到具体目标时，还要写清源结构与目标结构的对应、新增假设、竞争解释及反证标准。“原论文有效”不能直接推出“新问题有效”。领域专家可以聚合同类策略，但需保留成员论文的条件差异与反例，不按支持篇数投票。

新构建策略的 `transfer_status` 固定为 `unvalidated`。这是阅读与提炼阶段的记录，允许 `source_supported` 或 `source_inferred` 的来源状态；真实目标实验以后另挂证据，不能用计划冒充执行结果。

## 产物、程序检查与使用

paper/domain 请求使用唯一的当前契约。论文 `knowledge` 必须包含 `paper_understanding` 与 `reasoning_patterns`；领域知识也必须给出结构化策略或明确的空列表理由，并给出领域全景（演化链、争议、空白、评估协议）。技能保持按研究能力分类，目前共 21 项。

协调器将实际来源冻结，并生成以下分视图，供后续角色按需读取：

```text
library/experts/<expert>/<version>/
├── SKILL.md
├── asset.json
├── sources/...
└── knowledge/
    ├── index.md
    ├── paper-understanding.json
    ├── idea-trace.json
    ├── reasoning-patterns.json
    ├── communication-analysis.json  # 有表达分析记录时
    └── reuse-assessment.json         # 有复用评估记录时
```

领域资产只生成其实际拥有的分视图。SKILL 入口和索引是程序生成的导航，不是自动证明学会论文，也尚非完整的独立安装包。源文件、分视图和入口都记录哈希，历史版本不会被新经验覆盖。

程序检查来源路径/哈希、指定正文版本、源与导航引用对应、已读/未读集合、论证 ID 与无环依赖、策略到轨迹的链接。必要材料未读完可保存为 partial，随后进入 needs_evidence。程序无法单凭路径、哈希或图结构判断语义正确；独立资产审查需核查原文支持、公式条件、图表解释和策略反例。

契约不再分版本；旧契约创建的运行会被拒绝继续，需要 `run --new`。这次没有新增自动论文下载、图表提取服务、模型问答考试、跨项目检索或独立工具运行验证器。

## 写作图表学习与复用

[analyze-paper-communication](../../skills/knowledge/analyze-paper-communication/SKILL.md) 将写作结构和图表设计作为同一项表达学习：从实际材料记录章节/段落的论证功能、主张与证据的连接、变量编码、比较关系、不确定性呈现，以及可迁移做法的条件和失败情形。它复用理解阶段的已读锚点，不把叙事顺序当成真实发现过程，也不把图注当成已经观察到的图像。

[reuse-and-update-expert](../../skills/knowledge/reuse-and-update-expert/SKILL.md) 在项目内有旧候选时检查匹配与差异，保留适用知识，重读变化材料及受影响依赖，分别决定知识和工具能力是否降级。当前只自动发现同身份版本，实际复用决定由 worker 记录并接受独立审查，没有跨项目缓存或跳阶段机制。

两类结果可存入 `knowledge.communication_analysis`、`knowledge.reuse_assessment` 并生成上述分视图。这些可选扩展尚无专用 schema 强制；核心 v2 契约不变。图表重绘能力仍需真实数据、代码和执行证据，保存表达策略不等于已经完成重绘或新任务迁移验证。
