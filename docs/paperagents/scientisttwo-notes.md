# ScientistTwo 分析笔记

日期：2026-11-05　用途：[整体改造方案](redesign.md)的依据；原先的改造草案已由该方案取代

## 1. 背景与目标

PaperAgents 的目标是产出高质量论文。本次 `cir-reliability` 运行暴露的问题：

- 投入集中在实验前的文字论证（多轮质疑答辩、查新、综合、评审），最终只有一个 idea 进入实验；
- 瓶颈位置本应由实验回答，却在选队阶段被预判（“接受决策是核心、感知是次要”）；
- 下游没有消融、论文写作与基于实验的反驳。上游 AI-Scientist-v3 的多轮实验、消融、封存最终评测、事后分析、论文写作和评审能力不在 PaperAgents 主链上。

ScientistTwo（arXiv 2609.19644）在 107 个顶会任务上自报 86 个超过人类 SOTA、平均相对提升 25.2%，论文质量主要由 AI 评审判定（33 篇人工评估为与人类论文持平）。本文归纳其有效性的来源，确定可吸收的部分，并给出 PaperAgents 的改造方案。

## 2. ScientistTwo 的做法

每个阶段统一为“专职 agent 产出 → critic 判定接受 / 拒绝 / 打回 → 有上限的循环”。

| 序号 | 阶段 | 要点 |
| --- | --- | --- |
| 1 | 找局限 | Limitation Extractor 提取目标 SOTA 方法的局限，Verifier 反复核对至足够 |
| 2 | 种子 idea | 针对局限生成 N_seed 个，Novelty Checker（LLM）按新颖性排序，取前 N₀ |
| 3 | 子集复现基线 | 重跑人类 SOTA，不照抄论文数字 |
| 4 | 子集实验筛选 | Critic 判 Bad（丢弃）/ Good（放大）/ Engineer（调试后重判，超预算算 Bad） |
| 5 | 全集验证 | Good 的 idea 在完整 benchmark 上重跑 |
| 6 | 进化与选择 | Evolver 读取历史成功结果与失败日志，生成新 idea，并补入未测种子防局部最优；满 K 轮或 S 个成功后由 Selector 选出最佳 |
| 7 | 消融 | 规划 → 执行 → 判定；只保留严格更优的修改；归因并删除冗余组件 |
| 8 | 初稿 | 写作 agent |
| 9 | 评审与反驳 | 评审打分不足时，反驳 agent 设计并运行补充实验 |
| 10 | Meta-review | 未达会议水平则退回方法精炼 |

成本与局限（第三方摘要）：每任务约 2.5 天、3765 美元；ScholarPeer 评审在开发中使用过，不独立；失败任务不计入平均增益，无置信区间；子集筛选可能误杀只在全集有效的 idea；只适用于有现成代码和 benchmark 的计算型任务。

## 3. 效果好的根本原因

1. **问题有锚点且可测。** 从复现强基线开始，后续每一步都有明确比较对象，论文主张天然是“相对强基线提升多少”。
2. **证据在前，论证在后。** idea 由便宜的子集实验批量筛选，有工程预算防止被 bug 误杀，失败轨迹驱动进化。写进论文的是已经赢过基线的方法。
3. **方法由实验塑形。** 消融归因并精简，评审意见用补充实验回应，meta-review 可修改方法而不只是措辞。
4. **控制结构简单统一，并有完整性审计。** 产出者 + 批评者 + 有上限循环；核查分数可复现、规格符合、引用真实、方法与代码一致。

对照 PaperAgents：差距的根源不在构思写得好不好，而在于实验前的论证太重，实验与写作太轻。

## 4. 吸收、不吸收与保留

**吸收**
- 先复现基线并实测局限，再提出假设；
- 多个 idea 进入子集筛选，带工程调试预算；
- 失败轨迹驱动下一轮进化；
- 消融归因；
- 评审意见触发补充实验；
- 完整性审计（方法与代码一致、引用来自语料）。

**不吸收**
- 用 LLM 新颖性分决定实验顺序：分数本身未经验证；
- 单一标量和“严格更优才保留”：本任务 FAR₀ 与 Success₊ 是权衡，需同时比较；
- 只从一篇论文的局限出发：天然偏向增量改进。

**保留 PaperAgents 的长处**
- 多专家跨论文迁移：非增量创新的来源；专家负责发散，实验负责筛选；
- 实验前的有效性把关：本任务的评测集（含无解查询）需要构造，标签、泄漏与统计前提必须在实验前解决。

## 5. 阶段划分与工作量

ScientistTwo 第 3 节分为 5 个大阶段：生成种子 idea（§3.1）、评估 idea（§3.2）、精炼 idea（§3.3）、消融（§3.4）、写作与评审（§3.5–3.6）；Table 1 细分为 11 步。论文未给出分阶段工作量，只说明 “Idea refinement, peer review, and meta-review dominate the computational budget … because they repeatedly execute experiments and generate long contexts”。22 个 agent 中实验前构思只有 4 个。

本次 `cir-reliability` 运行（事件日志统计，含失败重试，约 40 worker 小时）：

| 阶段组 | 耗时 | 占比 |
| --- | --- | --- |
| 知识准备（逐篇阅读 21.6h、专家审查 4.0h、论文专家 1.1h、其他 1.8h） | 28.4h | 约 71% |
| 讨论（复核 4.1h、答辩 2.6h、提案 1.6h、质疑 1.5h、补证据 0.7h、其他 1.2h） | 11.7h | 约 29% |
| 实验 / 写作 | 0 | 0% |
