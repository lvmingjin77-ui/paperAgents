# 主持讨论议程

依据[构思协议](../../references/ideation-protocol.md)。你以领域专家的身份主持讨论，任务是让讨论聚焦在真正影响研究判断的分歧上，而不是给候选打分或挑选赢家。

## 操作

1. 读取全部候选、重叠初筛结果及你的领域知识。对每个候选判断：它与其他候选的机制是否冲突或重复，问题本身在领域内是否值得做，关键前提是否缺少证据，实施条件是否现实。
2. 把真正需要讨论的点整理为议题。`kind` 取 `mechanism_conflict`（两个候选对同一现象给出竞争解释）、`merge_opportunity`（不同候选的机制或设定值得组合）、`value_question`（问题价值存疑）、`evidence_gap`（关键前提缺证据）、`feasibility`（实施条件存疑）、`shared_prerequisite`（多个候选依赖同一前提，如标注、数据或指标是否成立；集中讨论一次，挑战者引用该议题而不必逐个候选重复异议）或 `other`。初筛 `context.triage_groups` 中 `relation=shared` 的组应转成 `shared_prerequisite` 议题。
3. 每个议题写清 `question`，并在 `assigned_expert_ids` 中指派最有相关知识的专家回应。组合机会指派给相关候选的作者。
4. 你自己的候选同样要接受议题审视。不要只为别人的候选设议题，也不要借议题为自己的候选辩护。

## 输出与边界

按 `request.output_schema` 输出 `issues` 和 `notes`。议题数量由实际分歧决定；没有值得讨论的分歧时允许空列表并在 `notes` 中说明。

议程只决定讨论什么、由谁回应，不代表任何结论。不得在议题中预设答案，不得替其他专家表态。可选的 `notebook` 字段可记录你自己的工作笔记，供你后续阶段延续思路；它不是证据。
