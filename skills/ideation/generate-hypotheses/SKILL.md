# 生成可检验假设

按[构思协议](../../references/ideation-protocol.md)和[证据规则](../../references/evidence-policy.md)开展独立思考。目标是有解释力且可检验的候选，不是让每个专家都交出一个看似新颖的标题。

## 操作

若任务含 `context.revision_context`，同时使用 [revise-hypotheses](../revise-hypotheses/SKILL.md)，依据真实旧候选与质疑逐项修订并保留谱系。首次独立提案没有该字段，不模拟上一轮讨论。

1. 读取研究目标、固定版本的领域知识及自身论文/专题知识。初始轮只使用自己的证据和已核验事实，不提前读取其他专家未提交的候选。
2. 从具体未解问题、矛盾结果、适用假设的变化、跨领域机制或评估缺口形成假设。说明为什么值得研究以及比最接近工作新增了什么。
   若使用已提炼的 `knowledge.reasoning_patterns`，在候选 `source_refs` 中记录对应专家、策略 ID/版本及来源轨迹；展开源问题到目标问题的对应、保持的机制关系、新增前提和可反驳预测。来源策略的 `unvalidated` 不能被默认为新任务已有效。没有适合的策略时可以直接从问题与证据提出新假设，不为套用策略强造类比。
3. 对机制逐步展开：干预如何改变中间量，再如何影响目标观测；指出必要假设、竞争解释和预期失败情形。迁移外部机制时保留源问题与目标问题的对应及差异。
4. 检查与已存在候选的机制重合，修补或扩展同一机制时保留谱系，不能通过换名称制造多样性。允许不同机制并存，不按单个模型分数过早只留第一名。
5. 为每个候选设计可判别预测和反证条件，必要时调用 [design-discriminating-experiments](../design-discriminating-experiments/SKILL.md)。暂不能解决的实现或证据缺口显式列入计划。

## 输出与验收

按[运行约定](../../references/runtime-contract.md)输出 `hypothesis` 的 `expert_id` 与 `candidates`。每位专家最多 `discussion.max_candidates_per_expert` 个（默认 2），宁少而精、彼此真正不同。

每个候选标注 `kind`：`mechanism`（新机制或新算法，是创新主体）、`diagnostic`（诊断或分析某现象的研究）、`baseline`（已知做法的组合或调参，作为对照）。不要把 baseline 包装成 mechanism。卡片保持简洁：每个字段写结论和关键理由，长推导、表格和实验细节放到文件，用 `source_refs` 或路径引用。机制卡必须包含问题、假设、机制、前提、最接近工作、反证、实验方案和来源；用允许的扩展字段记录谱系及未知。

预期结果不能写成实际观测。没有合格候选时允许空集合并说明原因，不为凑数提交无机制或无来源的方案。候选数量由研究覆盖与质量决定，不从“核心四位专家”机械推导固定数量。
