# 核查研究增量

使用[证据规则](../../references/evidence-policy.md)及[系统检索协议](../../references/literature-protocol.md)。本技能核查文献重叠，不能保证全球首次，也不能独立证明一个 idea 值得研究。

## 操作

1. 把候选拆成问题、关键机制、假设变化、理论结论、实现差异和评估贡献。区分真正技术增量与改名、常规组合、参数调整或任务换皮。
2. 用机制同义词、功能描述、相邻领域术语、已知最近邻及引文关系查询。更新到本次审查日期；新颖性检索不能只限制在领域语料的近三年窗口。
3. 获取最接近工作的正文/方法及相关补充材料，逐个比较“对方已做什么、本方案多了什么、差异为何影响可检验结论”。题名相似度、嵌入距离和搜索摘要只能筛选线索。
4. 对不利先例主动核实，检查多个来源是否其实指向同一版本。若只能看到摘要、搜索被截断或关键最近邻全文缺失，保留不确定，不能当作未见先例。
5. 提供每项贡献的对应证据、差异及不确定性；重大重叠可建议收窄或修订。修订后针对发生变化的贡献重新检索。

## 输出与验收

按[运行约定](../../references/runtime-contract.md)输出 `novelty.reviews`，包含 `idea_id`、`status`、`nearest_work`、`search_log`、`reason`。状态为 `distinct`、`overlap` 或 `uncertain`；`distinct` 必须写明检索范围和相对最近邻的具体差异。

检索日志保存实际查询、时间、服务、过滤器、结果及局限；无检索能力时不捏造日志。来源覆盖不足的关键贡献保持 `uncertain`，交给综合阶段判断是否需补证据。

协调器对 `distinct` 强制结构化检索日志，字段按运行约定与请求 schema 填写。真实零结果可以记录，不能把检索失败当作零结果，也不能因为需要引用而编造最近邻。

## 轻量初筛（`stage=triage`）

位于独立提案之后、讨论之前，作用类似去重与邻近聚类：让讨论尽早看到明显撞车。对每个候选只做少量查询，并查阅 `context.domain_graph` 中相近问题的论文卡。按 schema 给出 `overlap_risk`（`high`、`medium`、`low`、`unknown`）、`near_matches`、`search_log` 与写给讨论阶段的 `note`。`high` 不等于否决，`low` 不等于新颖；证据不足时不得据此淘汰候选，最终判断由讨论后的深度查新完成。

同时输出 `groups`，只归组真正需要作者处理的候选：`duplicate`（核心机制与可检验预测实质相同）、`partial`（主体相同、各有不同组件，可合并成一个更强候选）、`shared`（不同机制但依赖同一前提，如同一标注或数据条件；交给主持人作为共享前提议题）。同一主题或同一子问题不是重复；只在机制层面判断。每组给 `representative`（最完整的版本，其作者负责写合并版）和 `reason`。没有需要归组的候选时返回空列表。
