# 综合研究提案

使用[构思协议](../../references/ideation-protocol.md)与[运行约定](../../references/runtime-contract.md)。`ready` 表示可进入实验，不表示假设已证实。

## 操作

1. 检查候选、来源、挑战和新颖性审查的 ID 与版本对应，列出已解决、待实证及仍阻塞执行的问题。不能漏掉对最终选择不利的评审。
2. 比较候选对问题的重要性、机制增量、论证一致性、证据基础、可判别性及实施条件。采用可解释的逐项权衡，不由投票、Elo 或单一总分决定科学价值。偏向创新：风险可以由一个明确实验检验时，优先选择上限更高的 `mechanism` 候选，而不是更“安全”但增量小的方案。`baseline` 候选作为对照写进实验，不作为创新主体入选；若最终只能选 baseline，如实写明它是基线而非新方法。
3. 可补全不改变已审查科学主张、机制与关键前提的表达和执行细节。新增机制、改变核心假设或关键前提、组合产生新交互时，说明变化并输出 `needs_evidence`，将重新生成候选、挑战与查新列为阻塞动作。综合者不能自行修复核心；协调器可按 next_action 退回作者或分派补证据任务；`selected_idea_id` 只能指向已有候选作为来源，不能借用其 `distinct` 状态为实质新方案背书，也不能自行编造一个已注册的新 ID。
4. 给出一个明确主问题、机制假设和预期贡献，使用 [design-discriminating-experiments](../design-discriminating-experiments/SKILL.md) 完成执行、评价及反证计划。逐项映射到可调用工具、待开发部分和证据来源。
5. 保留有信息价值的 alternatives、未解决问题及将来切换路径的条件。负面结果也应能支持清楚的研究判断，不能承诺结果必然正向。

## 决策与输出

需要候选作者修订时，依照[假设修订协议](../../references/hypothesis-revision-protocol.md)说明退回原因和所需证据；综合者不能代替作者伪造回应。显式退回 `hypothesis` 才会把旧候选及其质疑交给对应专家。

- `ready`：提案仍是对应已受挑战和查新的候选，关键来源与增量已核查，重要异议有证据解除或转为设计明确的实验，方案具备可执行、可审计的评价与反证条件。剩余问题不得是阻塞项；没有作者实际回复时，不得把推测的回复算作已解除异议。
- `needs_evidence`：存在具体可解除的材料、实现、可判别性或新颖性缺口；给出所需证据与下一动作，不伪装完成。
- `no_viable_idea`：当前候选存在不能通过局部补证据解决的核心问题；列出理由及可保留的知识，不硬选赢家。

输出 `synthesis` 的决策、`selected_idea_id`、`proposal`、`alternatives`、`unresolved_questions`。阻塞问题用结构化条目明确 `blocking: true`。`ready` 的 proposal 包含完整实现计划、评价协议和来源，随后接受独立 [review-research](../../review/review-research/SKILL.md) 检查。

按运行约定复制 `context.candidate_targets` 的 `candidate_ref`，保留所选候选五个科学核心字段的原值；补充执行细节不允许替换原假设。收到 `revision_context` 中的旧综合和独立评审时，逐项处理真实阻塞意见，明确已解决与仍未解决的部分。

## 讨论循环之后的综合

v3 中，综合发生在作者答辩和原质疑者复核之后。`context.candidates` 只包含有效候选（已撤回或被作者新版本取代的不在内），`context.debate_ledger` 给出议题表路径和仍未关闭的阻塞异议。

- 选择 `ready` 时，所选候选不能有未关闭的阻塞异议（状态须为已解决或已转为实验）；程序会拒绝违反这一点的提交。
- 必须给出 `next_action`：`ready` 只能配 `proceed`；需要作者再修订时用 `revise_candidates`，若独立评审同意，协调器会自动退回作者（有次数上限）；缺材料、数据或执行条件时用 `gather_materials`；没有值得继续的方向时用 `stop`。
- 你也是领域专家，可能提出过自己的候选。`context.conflict_of_interest` 列出这些候选；选择或排除它们时要给出与其他候选同等标准的理由，独立评审会专门检查。
- 不论决定是否为 `ready`，都会进入独立评审。
- 可选 `secondary_ref`：若另一个有效候选机制不同、同样已通过查新且没有未关闭的阻塞异议，可复制它在 `context.candidate_targets` 中的引用，作为备选在同一实验中以 `program_2` 运行。不要为了多做实验而选择证据不足的候选；没有合适的备选时省略或填 `null`。

## 补证据闭环

独立评审同意 `gather_materials` 后，协调器会分派有轮数上限的 evidence 任务。报告通过 `context.evidence_reports` 提供，报告不是裁决，必须核对来源、适用候选和剩余缺口。

- 仅补事实且没有开放的阻塞异议时，直接重新综合并独立评审。不能仅凭 evidence 的 resolved 绕过对原始证据的检查。
- 证据改变前提、机制、数据或统计保证，或原讨论中仍有阻塞异议时，协调器先退回 hypothesis，让作者处理真实证据，再走质疑、答辩和复核。不得由综合者修改科学核心或替质疑者关闭异议。
- needs_human 只影响个别候选时，公平考虑其他候选；不得因一个候选需要人工就停止所有工作。若选中方案或全部可行方案都受同一外部资源缺口阻塞且不能绕开，输出 needs_evidence + next_action=stop，逐条说明用户要提供什么。
- 数据检查无法确定的事项可以保持 unresolved；可通过修改构造协议解决的问题交给作者，不自动要求人工。
- 效果和机制是否成立交给设计明确的编号实验必做项。统计前提、标签质量和评估泄漏必须有有效的检查方案；探索性实验也不能支持其前提尚不成立的统计保证。需要收窄原候选的科学主张时先 revise_candidates，不在综合中静默降格或改写。
- 不执行候选实验；run 仅推进 ideation，真正执行由用户通过实验入口启动。
