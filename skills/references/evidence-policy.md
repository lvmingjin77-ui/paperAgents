# 证据与研究思路标注

此文件约束所有知识、构思、工程和审查技能。它定义证据语义，不替代主程序的产物 schema、权限检查或阶段校验。

## 四种知识来源

每项影响研究决策的主张必须明确属于以下一种类型；复合句先拆成可单独检查的主张。

| 类型 | 含义 | 最低支撑 | 不允许的升级 |
| --- | --- | --- | --- |
| `source_fact` | 论文、补充材料、数据或代码直接报告的事实 | 精确来源、版本和可定位锚点；注明“作者报告”或实际执行来源 | 论文报告的性能不能自动成为本系统已复现结果 |
| `author_reasoning` | 作者明确写出的动机、推理、设计取舍或解释 | 对应段落、公式推导或作者明确说明 | 不能根据论文组织顺序推定作者真实发现顺序或内心思路 |
| `system_inference` | 系统从来源推导的解释、机制迁移或研究轨迹重建 | 支撑主张 ID、推导步骤、成立条件、竞争解释 | 不能改写成作者主张；重复被多个 agent 引用也不改变来源类型 |
| `unknown` | 来源没有说明、材料未取得、矛盾未解或证据不足 | 缺失内容、已检查范围、下一项可解除未知的行动 | 不能以常识补齐后伪装成论文事实 |

“证据明确”与“结论正确”是不同维度。保留作者报告与复现失败的两条记录，并说明条件差异；不要覆盖原始记录。未知不是负面结果，未运行不是运行失败，未找到先例不是证明不存在先例。

## 可追溯锚点

- 论文：稳定标识（DOI、arXiv ID 或官方论文 ID）、确切版本、全文路径或可访问 URL、章节/页码及相关公式、图表或附录编号。PDF 页码与印刷页码不同则分别注明。
- 代码：仓库来源、commit SHA、文件、符号和行号；行号只在该 commit 下有效。仓库链接本身不能支撑某段实现与论文一致。
- 运行：命令、代码和工具版本、配置、数据版本及划分、随机种子、环境、开始/结束时间、退出状态、完整日志及原始结果路径。指标必须能追到计算程序与输入记录。
- 检索：检索服务、精确查询、过滤器、时间、返回/筛选数量、去重规则、失败或截断情况。由搜索摘要转述的事实仍标作待全文核验。

保存支撑与反驳证据、适用条件及不确定性。不要把 agent 数量、模型自信、讨论共识、Elo 或审稿分作为科学真理的证据。

## 研究思路轨迹

为每篇核心论文建立：问题与观察 → 现有解释/方法的具体不足 → 假设或切入点 → 设计选择与替代方案 → 可区分的预测 → 实验及反证 → 结论与边界。

逐条标注上述来源类型。论文未交代“为什么不选另一方案”，应记录未知或系统推断。可以重建可理解的论证链，但称为“系统重建的论证轨迹”，不能称为作者真实研究历史。附录中的失败尝试、消融、敏感性、复现条件和限制与主结果同样纳入。

## 状态与传播

知识条目、工具执行和研究主张分别记录状态，禁止一个 `verified` 覆盖三者。知识完成核对不意味着工具能运行；工具通过测试不意味着复现论文结论；某数据集上的结果不意味着主张已普遍成立。

下游使用证据时携带来源 ID、版本与条件。修订证据后列出受影响的专家、idea、实验和论文段落，由对应阶段重新判断；禁止无记录地回填或静默改变已执行实验的预先标准。
