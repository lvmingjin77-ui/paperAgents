# 从论文到论证图

本协议用于 `trace-paper-ideas`。输入是固定版本的全文、补充材料及有来源的论文理解记录；输出是可追溯的 `idea_trace`，不承担作者心理或真实发现时间线的恢复。事实与推断分类沿用[证据规则](evidence-policy.md)，机器字段以当前任务 schema 为准。

## 先确定论文在论证什么

阅读引言、方法、理论、实验与限制之间的联系，逐项检查以下问题。它们是观察角度，不是必须伪造九个完整节点的模板；材料没有说明时记录未知，不能用领域常识替作者补齐。

| 角度 | 应提取的具体内容 | 需要防止的误读 |
| --- | --- | --- |
| 问题张力 | 想实现的目标与观测、约束或现有能力为何不能同时满足 | 把“性能仍有提升空间”当成有解释力的问题 |
| 先例瓶颈 | 哪项已有方法、哪段机制、在什么条件下受限；所据比较是否公平 | 把作者批评扩展到整个领域，或把未比较写成已失败 |
| 隐含前提 | 既有论证依赖什么可比性、独立性、可观测性或近似 | 系统发现的前提必须标为重建，不能称作者明确承认 |
| 关键洞察 | 哪个关系、反例或重新表述使新的方案可被考虑 | 只把新模块名称重新说一遍 |
| 机制选择与替代 | 为什么选该机制；可选替代是什么；取舍依据是什么 | 未尝试的替代不能写成作者实验排除的选项 |
| 形式化 | 洞察如何成为变量、目标、约束、算法步骤或可检查命题 | 公式出现不等于公式正确，也不证明作者怎样想到它 |
| 可判别预测 | 相对于最近邻和竞争解释，哪些条件下应产生不同观测 | 单纯“性能更好”不能自动区分机制 |
| 证据力度 | 实际证据支持了哪个较窄命题，还排除了哪些解释 | 消融收益不必然证明因果解释，计划不能当结果 |
| 失败边界 | 哪些前提失效、任务条件变化或反例会使结论不成立 | 未检验边界与已发现失败分别记录 |

先定位来源再提炼关系。对每条关键判断保存实际章节、公式、图表或附录锚点；引用整个标题或仓库首页不足以核查微观推理。

## 建立带 ID 的图

增强论文任务中，每项保留 `step`、`statement`、`basis`、`source_refs`，并包含以下字段。当前任务 `output_schema` 决定是否启用此契约；不要把增强字段要求强加给仍采用较小格式的语料任务。

| 字段 | 语义 |
| --- | --- |
| `trace_id` | 本论文图内唯一、重排后仍稳定的节点 ID |
| `depends_on` | 本图内支撑该节点的 ID 列表；无前置依赖可为空 |
| `reasoning_operation` | 具体论证操作；未知则说明哪一步尚无法重建 |
| `assumptions` | 该节点成立的前提列表，不能只列全篇公共假设 |
| `alternatives` | 仍需区分的解释、机制或设计替代列表；未提出时不捏造 |
| `testable_implication` | 可判别预测或检验方式；历史未知等不适用时明确说明 |

`source_refs` 使用 `{source_id, anchor_id}`，两者必须对应 `knowledge.paper_understanding.navigation` 中已读的来源锚点。非 `unknown` 节点需要非空引用；允许附 `locator` 等可读信息，但它不替代 ID 关系。正文事实与实验记录不能靠同一个不精确锚点互相冒充。

一节点尽量只表达一条主张或论证转折，使用稳定 `trace_id`。`depends_on` 指向本论文轨迹中它真正依赖的节点 ID：例如形式化依赖机制和假设，判别预测依赖形式化与竞争解释。并列实验可各自依赖同一假设，不必硬串成线性故事。

依赖图不得有重号、悬空引用、自依赖或循环。`step` 是展示顺序，ID 不因重排改变；边表示论证支撑关系，不表示时间先后。反驳、限定或替代关系可在 schema 允许的扩展字段中另记其关系类型，不能偷偷将“反驳”解释成支持依赖。对跨论文关系注明论文 ID 与版本，不借本论文局部 `depends_on` 引用其他图的裸 ID。

当实际发表论证存在循环时，记录“论证存在循环”的缺陷及涉及来源，拆出尚未获得独立支持的未知前提；不要给输出依赖图制造循环来模拟有效支持。缺失材料也不能用一条空泛节点连接所有步骤。

## 逐节点判定来源与证据

- `author_stated`：作者明确陈述了此论证或取舍；来源必须直接支持该联系。
- `reconstructed`：系统利用原文重建联系、补充替代解释或提出新的判别预测。说明原文提供什么、系统增加什么及增加的前提。
- `unknown`：未说明或无法建立联系。写清缺什么、检查过哪里以及何种材料能解除未知。

事实记录可在 `knowledge` 中使用 `source_fact`；把它组织成因果链时仍须判断链条是作者明确说明还是系统重建。同一个节点若混有作者论证和系统增补，拆开或把完整结论标为重建，不能让引用替系统推断“洗成”作者事实。

来源归属与证据力度是两件事。作者明确提出假设只说明“作者这样主张”，并不证明假设成立。分别说明证据是形式论证、作者报告、系统实际检查还是待执行计划；注明条件、对照、替代解释和不能推出的结论。未运行不等于反驳；缺材料不等于负面结果。

## 从图交给策略提炼

图回答“本文公开材料如何支撑这一论证”。另用 [distill-reasoning-patterns](../knowledge/distill-reasoning-patterns/SKILL.md) 回答“其中何种操作可在新问题里尝试”。将节点 ID 与来源交给策略，不把每个节点机械转成一种策略。

验收时沿主结论反向追踪：每个关键前提来自何处，哪个跳步仍是未知，哪个证据只支持较弱解释，哪个边界尚未检验。再正向追踪预测与反证条件，确认没有把预期结果写成实际发现。具体练习见[虚构示例](idea-trace-example.md)。
