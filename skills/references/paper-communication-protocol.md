# 论文论证与图表表达协议

本协议学习论文如何组织和展示证据，产物供后续构思、实验呈现与论文写作检索。科学理解已有的 `analysis.figures_tables` 判断图表说明了什么；这里进一步记录为何这种组织有助于或妨碍判断，以及何时可以迁移。两处引用同一来源，不重复维护不同版本的数值或结论。

## 入口与分析范围

从论文专家的来源清单、章节/图表导航和科学分析开始。按真实论文类型选择观察单位：实证论文可沿主张—实验—图表组织；理论论文可沿定义—命题—引理—证明—边界组织。没有算法图、实验表或统计误差条的论文，不强加这些项目。

`source_refs` 使用 [论文理解协议](paper-understanding-protocol.md) 中匹配且已读的 `{source_id, anchor_id}`。一条观察同时依据图与文字解释时同时引用两处；必要时在原导航登记更细的真实锚点，不创建独立且会失去对应关系的第二套导航。没有取得图像时，可引用已读图注分析图注文字，但不能把图注锚点当成已看过图的证据。

每项记录的 `basis` 使用 [证据规则](evidence-policy.md) 的四类值：

| 值 | 本协议中的含义 |
| --- | --- |
| `source_fact` | 能从材料直接核实的结构或表达事实，例如正文先呈现总效果再呈现消融 |
| `author_reasoning` | 作者公开说明选择这种解释或呈现方式的理由，有直接来源 |
| `system_inference` | 系统对组织目的、读者认知负担或可复用设计原则的分析 |
| `unknown` | 材料缺失或作者未解释，无法确定；明确缺口，不用通行习惯补齐 |

“作者把消融放在主结果后”可被观察；“作者先完成主实验才想到消融”不能由章节顺序推出。“这种顺序便于先判断整体效果”通常是系统分析，不应冒充作者意图。

## 写作与论证结构

沿一个关键主张追踪其提出、定义、证据、限定和讨论的位置，分析各单元承担的作用。以下问题按实际内容选用，不要求为每篇论文填满同一个章节模板。

| 观察对象 | 要保留的可复用知识 |
| --- | --- |
| 标题与摘要 | 研究对象、问题、方法、结果与范围如何压缩；量化结论是否保留基线、任务与条件；哪些措辞超出证据 |
| 引言 | 从领域问题缩小到具体可检验缺口的路径；现有方法的限制如何得到证据；贡献是否对应这个缺口 |
| 相关工作 | 比较按什么机制、假设或评价差异组织；何处真实承认前人的能力，何处只用弱化对手的表述制造新颖性 |
| 方法与证明 | 符号和条件何时出现，读者是否需反复跳转；设计选择怎样连接问题；定理、引理与证明分层是否隐藏关键前提 |
| 结果 | 每项实验回答哪个问题，主结果、消融、机制、鲁棒性及失败结果的次序；主张、证据和解释能否分开识别 |
| 讨论与局限 | 把结论推广到哪一层，哪些限制进入主文、哪些埋在附录；未知、负面结果与下一步是否明确 |
| 关键段落与衔接 | 段落的功能及与前后段的逻辑关系，例如提出可检验预测、给出判别结果、收紧解释；记录功能与依赖，不逐句仿写 |

对被标作“研究缺口”的内容，核对它是未解决的科学问题、证据缺口、适用条件限制，还是仅更换命名/场景。对每个重要转折记录需要什么证据才能成立；不能因为写法有说服力就采纳该科学判断。

可保留 `claim_links` 或真实 `trace_id` 扩展帮助连接已有主张/轨迹；这些 ID 必须已存在。未建立主张编号时直接使用来源锚点和短描述，不编造被引用对象。论文中没有披露的研究失败史、发现顺序和作者心理保持未知。

## 图表表达

逐项处理承载关键论证的图表及其 panel、图注、表头和脚注，保留它解决的比较问题。覆盖范围按主张重要性和实际材料确定，不规定凑齐多少张图或多少条技巧。

| 维度 | 分析问题 |
| --- | --- |
| 读者任务 | 是看机制、比较组间效果、判断趋势、分布、异质性、代价权衡还是证明失败边界？一个图是否混入无关问题？ |
| 数据与统计对象 | 展示的是原始点、聚合量、模型预测还是概念示意？分析单位、样本量、分母、筛选与聚合规则是否可见？ |
| 视觉编码 | 位置、长度、颜色、形状、线型与 panel 分别表示什么；相同颜色或坐标是否跨 panel 保持语义；连续量是否被不当离散化？ |
| 比较与尺度 | 基线、对照、排序、归一化和共享坐标如何支持比较；截断轴、对数轴、不同范围或双轴是否会改变直观印象？ |
| 不确定性 | 误差条、区间、重复点及缺失结果怎样呈现；定义未写时明确未知，不能从形状推断 SD/SE/CI 或显著性 |
| 表格组织 | 行列维度、分组表头、单位、脚注、粗体/排名标准、缺失符号；不同数据集或指标的值是否允许汇总或比较？ |
| 图注与正文连接 | 图注能否说明条件与编码，正文究竟引用哪个 panel/单元格；图与论点之间是否有解释跳跃？ |
| 可见限制 | 模糊图像、颜色辨识困难、不可读标签、选择性展示、遗漏基线或不明统计口径；区分可见事实和可能风险 |

数字结论由已有科学分析和真实数据支持。不能从低分辨率图片读取精确值，不能把视觉间隔等同于显著性，也不能通过改变尺度增强尚未成立的结果。机制示意图表达的是机制主张，不自动提供实验因果证据。

若有实际绘图脚本或数据，记录绑定的仓库版本、文件入口、输入数据和既有验证证据；可使用 `code_refs` 指向已登记工具或冻结材料。`documented`、`wrapped`、`tested`、`reproduced` 等方法能力仍由代码技能独立判定，未执行的绘图程序只能记录可定位，不能宣称已经重绘成功。

## 提炼表达策略

一项可复用策略应回答：什么读者问题触发它，已有何种证据和数据，具体改变哪些组织或表达关系，怎样检查它没有扭曲事实。保留适用条件、失败方式、替代方案和来源；“结构清晰”“图表美观”“学习顶会风格”不足以构成操作。

例如，可以从真实来源归纳“先展示相同预算下的总体效果，再用只改变一个因素的对照解释差异”。其条件是确有可比预算和相应对照；如果实验同时改变多个因素，就不能沿用机制归因的叙事。这个策略本身不是要求必须按此顺序写作，也不是可以省略相反证据的理由。

图表策略同样带条件。例如，针对同一单位上成对比较的方法，可考虑保留配对关系的展示；如果只是不同总体的独立样本，就不能画连线暗示配对。对范围差异较大的指标，应明确量纲和标准化依据，不能为视觉整齐把不同量当成同一个量。

优先复用结构、证据组织和数据到视觉的映射，不复制原文句子、图像或特色样式。向新任务迁移时，必须重新填写目标主张、数据和限制，并核对结论强度。原论文的结果、误差条和显著性不能成为目标图表的占位数据。

## 结构化产物

按当前任务 schema 保存 `knowledge.communication_analysis`，不替代 `paper_understanding`、`idea_trace`、`reasoning_patterns` 或 `code_tools`。当前它作为 `knowledge` 的可选扩展保存；本协议的结构和引用要求由 worker 与专家审查执行，程序尚未为此扩展做专门的字段、语义或引用关联校验。资产冻结和文件哈希核验也不代表这些分析正确。

| 字段 | 内容 |
| --- | --- |
| `status` | `analyzed`：已完成本次范围的分析；`partial`：部分完成但有影响判断的材料/检查缺口；`unknown`：缺少足够材料；`not_applicable`：本次材料确无可分析的表达内容，必须解释。没有图表不意味着整篇的写作结构不适用 |
| `writing_structure` | 数组，记录论证路径、章节/段落功能、衔接、证据与限制的安排；每项有 `id`、`summary`、`basis`、`source_refs` |
| `display_patterns` | 数组，记录实际图表的比较任务、数据/编码/尺度/不确定性/图文关系；每项有 `id`、`summary`、`basis`、`source_refs` |
| `transfer_recipes` | 数组，记录可迁移操作；每项有 `id`、`summary`、`basis`、`source_refs`、`preconditions`、`failure_modes`、`adaptation_checks` 和 `transfer_status: unvalidated` |
| `limitations` | 字符串数组，说明缺失/未读内容、不能确定的呈现意图、没有图表或尚无可归纳策略等情况，并说明影响 |

三个数组可为空，但要在 `limitations` 区分没有相应内容、材料未取得和没有可靠归纳。`partial/unknown/not_applicable` 不能只贴标签，须有非空原因。每个非 `unknown` 条目至少引用一个真实已读锚点；引用只能支持实际观察的范围。未知条目允许空引用，说明还需要什么材料；不得用未读锚点充当已分析证据。

在以上公共字段外可按需要保存细节，例如：

- 结构条目：`unit`、`reader_question`、`argument_role`、`evidence_link`、`scope_control`、`claim_links`。
- 图表条目：`display_kind`、`comparison`、`encoding`、`scales_and_units`、`uncertainty`、`caption_alignment`、`observed_limitations`、`code_refs`。
- 策略条目：`target_question`、`operation`、`required_evidence`、`alternatives`、`derived_from`（真实结构/图表条目 ID）。

不必给无关字段填模板。条目 `summary` 应写具体观察或操作，不能只填一个图号或“采用优秀叙事”。来源事实、作者明确理由与系统策略归纳分条或在同一条目内明确划分；不要把混合内容整体标成原文事实。策略通常为 `system_inference`，来源中明确陈述的原则可以标为 `author_reasoning`，但两者都不证明在新任务中有效。

## 审查与复用

沿条目回到真实页面核对：观察是否准确，局部图表是否被概括成整篇特征，图注与图像是否混同，叙事顺序是否被误写成发现过程，漂亮表达是否掩盖科学限制。再检查迁移策略能否由其他专家据此判断何时使用、何时停止，以及目标数据能否支撑同样的表达。

既有版本已完成且来源未变时，可以复用这些观察；论文版本、核心结果、图表或理解发生变化后，只更新受影响条目和依赖策略，并保留原来源与旧版本关系。资产复用与更新遵循项目的专家生命周期；不得仅凭“顶会论文”或表达流畅把未核查策略提升为通用方法。
