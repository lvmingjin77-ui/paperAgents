# 从论证图提炼研究策略

本协议用于 `distill-reasoning-patterns`。策略是有来源、有条件的操作知识；它不是作者人格模拟，也不是“成功论文都这样思考”的通则。先用[论证图协议](reasoning-trace-protocol.md)建立来源与依赖，再选择值得复用的变换。

## 识别可复用操作

一条策略须能说清：**什么张力触发它，原来的表述是什么，具体做了什么变换，变换后得到什么新问题或假设**。保存来源论文/版本、轨迹节点及原文锚点，标明是作者明确提出的策略还是系统归纳。

不要把方法名称当策略，也不要把“多角度思考”“做类比”当作操作。每条策略需保留不变量与所依赖的前提：变换后什么仍应保持，什么前提被放松或新增。找不到具体变换或不能区分来源的条目暂不入库；在限制中说明缺口。

## 八种操作提示

下表是**虚构微例与检查提示**，不宣称某篇论文实际采用过这些操作，也不证明其新颖或有效。按论文选择相关操作，不要求每篇凑齐类别，不以类别数量评价质量。

| 操作 | 触发与 before → operation → after | 必须检查的边界 |
| --- | --- | --- |
| 换表示 | 跨设备残差不可比 → 用条件正常尺度表达残差 → 检验误报率是否更可比 | 尺度差异若本身是故障，变换可能删掉目标信号 |
| 检查边界情形 | 理论声称任意噪声下有效 → 代入零噪声和高噪声极限 → 暴露适用区间或缺失项 | 极限推导的条件与实际任务是否可达 |
| 挑战默认前提 | 算法假定样本独立 → 构造同源样本强相关的情形 → 改写有效样本量问题 | 反例是否符合原方法声称覆盖的范围 |
| 分解瓶颈 | 端到端效果下降 → 分离检索覆盖与生成条件错误 → 选择真正受限的环节干预 | 分解是否遗漏交互；分别改善不保证端到端改善 |
| 改写目标 | 平均误差好但少数群体失败 → 显式约束群体风险 → 比较风险分配与平均表现 | 目标改变是否仍解决原问题，代价是否透明 |
| 机制类比 | 稀缺标注的分配问题 → 映射为信息采集与候选解释区分 → 设计自适应采样 | 可对应的是机制和决策结构，不能只因词语类似而迁移 |
| 干预与反事实 | 模块加入后性能提高 → 预算匹配并替换为无关模块 → 区分机制与容量解释 | 对照是否真正匹配、干预是否引入新混杂 |
| 组合互补机制 | 一个模块增覆盖、另一个抑噪 → 明确二者的因果交互并做组合对照 → 判断联合价值 | 单独有效不证明组合有效；保留负交互和失败条件 |

## 策略与具体迁移分开

通用索引保存适用条件和反例；迁移到目标 idea 时另给出来源结构到目标结构的映射，说明保留的不变量、目标新增前提以及哪些对应尚未成立。不能仅写“把 A 用于 B”。无具体目标时如实保留未迁移状态，不杜撰新问题来填字段。

一次迁移应可追溯到目标 idea ID、使用的策略版本和来源轨迹，并包含至少一项能区分迁移解释与竞争解释的预期观测，以及何种结果会反驳或限制该迁移。效果不显著、实验功效不足、实现失败和机制被反驳必须区分。思想来源关联与实验结果关联分别保留。

## 证据状态与跨论文合并

增强任务的 `knowledge.reasoning_patterns` 是结构化列表。每项必填 `pattern_id`、`name`、`problem_type`、`reasoning_move`、`preconditions`、`failure_modes`、`source_refs`、`trace_refs`、`evidence_status`、`transfer_status`、`test_plan`。前提和失败模式都要非空；确实无法建立策略时列表可为空，但需要非空 `knowledge.reasoning_patterns_reason`。

| 字段组 | 写法与证据边界 |
| --- | --- |
| `problem_type`、`reasoning_move` | 明确触发的问题类别和实际变换；可用 `trigger`、`transformation` 扩展展开 before/operation/after，不改变必填字符串类型 |
| `preconditions`、`failure_modes` | 适用前提及反例/失败边界；可用 `invariants` 补充迁移中应保持的机制关系 |
| `evidence_status` | `source_supported` 表示来源直接支持这一操作及其表述；含系统归纳或扩展时用 `source_inferred`。两者都不表示迁移有效 |
| `transfer_status`、`test_plan` | 当前仅允许 `unvalidated`；检验计划说明需要什么证据，不能把计划当结果 |

**论文策略**的 `source_refs` 是非空 `{source_id, anchor_id}` 列表，指向本论文已读导航；`trace_refs` 是非空 `{paper_id, trace_id}` 列表，论文 ID 必须为当前论文，节点必须真实存在。

**领域策略**的 `source_refs` 是非空 `{paper_id, locator}` 列表，论文须在 `source_paper_ids` 中。`trace_refs` 仍使用 `{paper_id, trace_id}`，有引用时指向真实语料节点；领域阶段若尚无稳定轨迹 ID，可以为空，但该策略须写非空 `trace_link_limitations`，解释当前追溯粒度，不能引用尚未构建的论文专家图。

具体目标迁移可用 `target_transfer` 扩展记录 idea ID、策略 ID/版本、source→target 映射、保留不变量、新增假设、竞争解释、区分预测和反证标准；无目标时注明未应用。该扩展不把 `transfer_status` 升级。后续真实实验另关联运行证据与目标版本，不覆盖构建时的状态。

分别记录策略的来源归属、原论文支持、系统检查和目标迁移证据。阅读过多篇摘要不会自动增加证据强度；作者报告的实验不自动等于本系统复现；迁移到新目标后证据状态不能继承为“已验证”。

领域专家可对多个论文中的相似操作建立策略族，但先比较操作、依赖前提和效果是否真的同构。每个成员保留论文/轨迹引用、差异及反例；矛盾结果可能意味着适用条件不同，不能简单按篇数投票。只从一篇得到的归纳应标明单来源范围，不以抽象措辞包装为通用定律。

验收时检查：别人能否据此识别何时使用、实际做什么变换、何时不该使用，以及如何证伪一次迁移。无法回答这些问题的“策略”只是标签。字段映射见[知识布局](knowledge-layout.md)，完整虚构练习见[示例](idea-trace-example.md)。
