# 专家复用与增量更新协议

本协议服务于领域、论文专家构建与后续资产审查。复用对象是可追溯知识及明确条件下的能力证据，不是角色提示词、聊天历史或一个通过标签。遵循当前[运行约定](runtime-contract.md)，知识来源、论证与工具各自遵循已有协议，不另建一套研究内容格式。

## 当前能力与操作边界

请求提供项目 `asset_library` 路径，并按 `expert_id` 将库中发现的 `asset.json` 路径放入 `context.reuse_candidates`。这只是身份检索，不是语义匹配、完整性证明或验收；worker 仍需检查实际文件与适用条件。候选非空时构建任务加载本技能，流程仍正常构建并独立审查。候选为空不证明全局不存在可复用知识，也不触发跨项目搜索。

协调器的 `freeze_asset` 创建不可覆盖的版本及来源文件清单，`verify_asset` 核对已记录元数据和文件哈希；完整性核验不判断适用性、不证明科学正确性或实际调用发生。没有 `_asset` 的普通 JSON 不能因 `verify_asset` 未报错就称为冻结资产已验证。

当前没有跨项目缓存索引、导入命令、自动迁移路径或复用跳阶段机制。其他项目提供的材料按普通候选来源核查，不声称已经导入或可以直接运行；本技能不实现这些功能。不把资产版本 ID 当作论文版本或单个文件 SHA-256：分别记录实际来源版本、文件摘要、专家契约版本及资产版本。

优先读取候选 `asset.json` 与存在的 `knowledge/index.md`，随后按需加载理解、轨迹、策略和原始材料。v1 资产可能没有分视图，直接检查原记录；不能假定新版视图已经生成。若复用成立，保留原知识和证据锚点，围绕本次任务抽查关键依赖即可，不强制每次重新提取全部正文。

## 逐层匹配

| 检查 | 判断依据与不匹配时的行动 |
| --- | --- |
| 完整性 | 读取实际快照，核对元数据、来源及派生文件的记录摘要。注明核验方法、结果及日志；缺文件、哈希变动或未核验不能写成通过。损坏资产不作为可信基线，可从独立完好的原始来源重新构建 |
| 来源身份与版本 | 论文 DOI/arXiv 等身份、正文/附录的实际版本和 SHA-256、代码 commit 或文件摘要、数据版本。标题、文件名、摘要相同不够；重新排版导致字节不同也需检查语义差异，不能直接判作同一已读版本 |
| 范围 | 当前方向、检索时间窗、语料覆盖、任务/人群/数据、假设、评价协议、目标能力。领域地图可能需要补新论文与分歧；单篇专家不因来源更新就扩大为领域专家。范围扩大时只复用仍成立的子集 |
| 契约与引用 | 按当前请求版本核对必填字段、来源与锚点、论文/轨迹 ID。历史自由文本不自动变成 v2 结构；真实重新核对后可补结构，仍无证据的项目保持未知。ID 变化需记录明确映射并核验指向，不能仅重命名以通过校验 |
| 知识审查 | 旧 `expert_review` 必须对应候选的实际版本及检查范围；核对失败项、限制与未决问题在本次是否关键。旧通过可减少重复核对，不能替代本次提交后的独立审查；缺失审查记录不能以文件哈希补足 |
| 工具与复现 | 对照实际验证记录中的源码/封装/测试版本、接口、解释器与依赖、平台/硬件、数据/划分/权重、随机性和评价协议。文本匹配不支持继承执行能力；旧成功只支持其已覆盖的条件，未知差异需要补检查 |

匹配项使用 `match|partial|mismatch|unknown`，分别表示所声明范围相符、仅部分相符、已发现冲突、证据不足；每项附实际依据及影响。没有工具等不适用情况使用 `not_applicable` 并说明理由，不伪装为一次验证通过。

## 决策与变化传播

- `reuse`：目标范围内来源、知识和必要能力已有足够依据，只需组织当前完整产物和当前审查，不重新提取未变化材料。
- `incremental_update`：保留有效子集，补变化材料及受影响的依赖；同时可降级一部分能力。
- `rebuild`：候选有基础性失效，或无法划清失效影响范围；说明需要重建的范围，仍可引用独立核实的原始来源。
- `no_candidate`：当前可见库中没有适用候选，按正常专家构建操作继续；不声称完成了全局缓存搜索。
- `defer`：必要来源、范围或验证条件不足以判断或完成更新。保存真实缺口，向协调器报告下一步；该值本身不是程序状态转换，也不绕过当前任务格式与晋级规则。

更新先列差异，再沿来源→主张→论证依赖→策略前提→方法实现/评价的关系检查影响。新反例可能使旧知识降为有条件成立或撤回，即使源文件完全没变。新增补充材料可能改变正文解释；新增论文可能改变领域结论而不改变某篇论文的阅读事实。无法确定是否受影响的节点列为待复核，不默认沿用。

保留未变条目的稳定 ID、来源与适用条件；对修改、撤回和新增项记录原因、证据及受影响条目。实际改变了源版本或锚点时检查全部相关引用。当前 schema 没有自动依赖失效引擎，这些传播由 worker 记录、审查者核对。

更新 v2 论文专家时仍需完整 `paper_understanding`、`idea_trace` 与策略字段。实际文件及哈希必须与本轮材料相符，完整阅读须包含被分配的正文版本；不因旧版声称已读就把新版全部锚点标已读。覆盖不足可保存但不能晋级。领域更新仍需满足当前语料 ID 与范围要求；旧库不能替代本轮检索覆盖证据。

## 工具能力降级

历史验证记录保持原样，当前 `code_tools[].status` 按当前能力证据重新决定，遵循[方法工具协议](method-tool-protocol.md)。没有可定位实现时至多 `documented`；存在封装但当前执行条件未得到支持时为 `wrapped`。`tested` 需要与所声明调用/行为范围匹配的真实记录；`reproduced` 还需要匹配的目标结论与评价协议。

源码、测试、环境或数据改变时，确定哪些证据失效并重验相关性质，不能仅更新哈希继续沿用通过状态。搬到新目录/机器后，路径映射不证明依赖或权重可用；需要当前环境真实调用支持运行能力。复用完全相同条件的历史测试时明确写“沿用历史证据”、绑定其版本与范围，不写本轮已执行。无法证明条件相同则降级或暂停该能力。

知识仍可用于解释原方法，同时禁止依赖尚未支持的当前运行/复现能力。`allowed_uses` 与 `blocked_uses` 是交接约束，当前运行时不自动执行这些限制。原论文成绩、策略相似性、旧代码文件与资产哈希都不能作为新任务已经复现或策略迁移成功的证据。

## `knowledge.reuse_assessment` 建议字段

这是 `knowledge` 下的可选扩展记录，不替代正式知识字段。当前 schema 可容纳这些数据，但未逐项强制校验，也没有根据它自动复用的 runner。v2 资产可生成 `knowledge/reuse-assessment.json` 与索引链接；这是已提交记录的检索视图，不增加验证证据。

| 字段 | 结构与语义 |
| --- | --- |
| `assessment_version` | 整数 `1`，仅表示本记录格式 |
| `decision`、`reason` | 上述五种决策之一，以及与证据相符的理由 |
| `target` | `{task_id, expert_id, scope, required_capabilities}`；实际任务身份、范围说明及能力字符串列表 |
| `base_assets` | 候选列表，每项 `{expert_id, asset_version, asset_path, asset_json_sha256}`；只记录实际值，缺失用 `null` 并说明。`asset_json_sha256` 是实际文件摘要；不是 `_asset.version` |
| `checks` | 每项 `{aspect, status, evidence, impact}`；`aspect` 为 `integrity|sources|scope|contract|knowledge_review|tool_verification`，状态见上文，`evidence` 引用实际文件/条目、版本、观察及核验方法。可按来源或工具重复该类检查 |
| `retained_items` | 每项 `{base_asset_version, item_ref, source_refs, reason}`，定位保留的实际知识条目及适用理由；没有稳定 ID 时使用准确 JSON 路径等定位，不虚构历史 ID |
| `delta_actions` | 每项 `{item_ref, action, reason, affected_items, source_refs, status}`；`action=add|revise|withdraw|recheck`，`status=planned|completed|blocked`。保留项与待做项分开；写出变化引起的实际依赖影响 |
| `capabilities` | 每项 `{name, kind, previous_status, current_status, allowed_uses, blocked_uses, verification_evidence, required_checks}`；`kind=knowledge|tool`，知识状态 `supported|limited|unavailable`，工具状态沿用 `documented|wrapped|tested|reproduced`。无既有状态用 `null`；当前工具状态与正式 `code_tools` 一致，历史证据不抹去 |
| `review` | `{status, evidence, remaining_checks}`；`status=pending|passed|failed|unknown`，指当前版本独立审查。构建者提交时通常 `pending`；候选的旧通过写在 `checks`，不能用它预填当前通过 |
| `limitations` | 非空缺口说明或空列表；包括未检查范围、旧契约缺项、来源缺失及无法支持的能力，不复制空泛免责声明 |

`source_refs` 遵循所在知识字段的来源规则；证据引用可使用允许的结构化扩展，但应能回到具体文件、哈希、锚点或日志。无候选时 `base_assets`、`retained_items` 可为空，写明实际查找范围；检查没有发生则 `unknown`，不为填满表格编造结果。评估不能保证完成时，仍按任务 schema 提交可表达的真实限制，无法满足必填项则报告受阻而不伪造合法产物。

## 提交与独立审查

本技能输出普通当前专家产物，而非差分 JSON 或旧资产路径。从旧记录保留科学内容时去掉协调器拥有的 `_asset`，使用本轮 `expert_id`、真实来源及正确引用；通过 `source_paths` 提交实际使用的材料、工具和证据文件。可以指向已存在的稳定冻结文件，但不要把整个 `library`、缓存或全局环境提交为来源。协调器生成本次快照，不覆盖旧版本；内容寻址版本也不承诺跨路径、跨项目物理去重。

后续 `expert_review` 核对保留项是否真的适用、差异是否传播完整、能力降级是否一致以及当前验证证据。新审查结果存在独立审查产物，不回写已冻结的 `reuse_assessment.review`；读取时关联本次任务与资产版本，构建时 `pending` 记录不会因此成为错误历史。审查者可补实际检查，但当前没有自动问答测评或强制独立工具重跑阶段。保留失败与旧版本，只有当前流程实际验收后才称当前资产获准使用。
