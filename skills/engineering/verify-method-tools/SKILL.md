# 验证方法工具

按[方法工具协议](../../references/method-tool-protocol.md)分别核查映射、调用、行为和结果，不以一次 smoke test 证明完整复现。

## 操作

1. 固定待测工具版本及所验证主张，检查实现方式、上游锚点、调用契约、依赖和所需权限/资源。记录封装源码、测试代码、输入、预期与环境文件的版本/哈希；测试后再确认被测文件未发生未验证变更。运行条件缺失就记录受阻项。
2. 在实际提供的执行环境调用登记的真实入口：CLI 要经过参数与序列化路径，Python 要调用公开符号，MCP 要通过客户端调用实际 server。import 成功、工具列举或测试未被入口调用的辅助函数，都不足以证明工具可用。检查正常/错误输入、输出内容、用户输入是否被意外修改及重复调用的产物隔离。
3. 对原实现封装，用相同输入直接调用固定版本的上游实现获取参考结果；改变有效输入与支持的参数，检测硬编码演示值、被忽略参数和语义漂移。对重新实现，用解析解、独立实现、已知实例或受控对照核查；预期不能来自待测实现本身。核对有意义的数值、标识符、顺序、单位与非有限值处理，事前说明容差；必要时检查完整数组或图像内容，不能仅检查形状/文件存在。
4. 若目标包含复现，先核对原论文数据、划分、预处理、预算、种子、指标与基线，再执行足以检验该结论的实验。资源少的运行只能支持其可判别范围，不强制以廉价小实验代替核心验证。
5. 保存实际 argv/API 参数、工作目录、解释器/环境、开始/结束时间、退出或异常状态、日志、原始输出，以及“预期—观察—比较规则—结论”。将记录绑定到此次被测源码与测试版本，格式见[调用与验证示例](../../references/method-tool-example.md)。分析失败来源：接口、实现、协议不等价、统计不充分或结果不支持；不放松断言、改写参考结果或反复挑 seed 来制造通过。
6. 修改实现或实验协议后重跑受影响检查，保留变更和原始失败记录。没有新变更或未决问题时不机械扩大测试范围。

## 输出与验收

按[运行约定](../../references/runtime-contract.md)更新工具状态及验证证据。`tested` 说明具体测试已通过；`reproduced` 必须注明复现了哪个结论、在何种条件下，以及允许的偏差。

Mock/dry run 只说明对应模拟路径。无法运行、结果不充分或未复现必须保留；不能将“测试进程退出 0”直接转换成“科学主张成立”。

注明执行者与实现者的关系：构建者自测和独立复验分别记录。当前调度器没有独立的强制工具测试阶段；`expert_review` 审核资产、版本和证据，可在实际权限与环境允许时复验相关调用。仅阅读报告只能说明报告审查完成，不能写成独立运行已通过；需要但未能完成的关键复验记为 `unknown`，不能靠更换角色名称补足。
