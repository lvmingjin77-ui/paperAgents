# 映射论文与实现

阅读[方法工具协议](../../references/method-tool-protocol.md)和[证据规则](../../references/evidence-policy.md)。静态代码阅读可以支持映射，不能支持已经运行或复现的结论。

## 操作

1. 确认代码与论文的关联及来源，记录仓库 URL、commit SHA、许可证、分支/发布版本、依赖、数据和权重要求。非作者代码标明身份；版本不匹配保留差异。
2. 从论文关键公式与算法步骤向下查到符号实现，并从训练/推理/评估入口向上反查其真实调用路径。不能只用名称相似认定对应。
3. 建立映射：论文锚点 → 代码文件/符号 → 配置/参数 → 输入与输出 → 已知差异。重点检查预处理、损失、采样、默认超参、随机性、数据划分、指标计算及 checkpoint 加载。
4. 找出可作为工具边界的最小完整能力，例如一个方法变换、预测器、训练入口或评估器；说明哪些能力只能在完整环境中调用。
5. 对未实现公式、隐藏依赖、不可取得数据、评估差异及可能影响结论的实现细节逐项记录。不在静态检查阶段自动执行来源仓库脚本。

## 输出与验收

输出调用方 schema 中的工具/映射记录，见[运行约定](../../references/runtime-contract.md)。至少能从每项重要方法行为定位到固定源码，或明确“未找到实现”。

仅完成映射使用 `documented`；没有实际封装、测试或复现证据时不升级。后续工程师应能据此明确要封装的接口及尚需解决的条件。
