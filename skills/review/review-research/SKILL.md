# 独立研究审查

按[证据规则](../../references/evidence-policy.md)、[构思协议](../../references/ideation-protocol.md)和[运行约定](../../references/runtime-contract.md)检查实际产物。先独立判断，再读取已有讨论；审查分数或模仿审稿人口吻不能代替证据。

## 检查重点

1. **问题与来源**：问题是否具体且重要，领域覆盖与全文缺失是否被诚实披露，事实/作者思路/系统推断/未知是否分开，关键引用是否真正支持主张。
2. **研究增量**：最接近工作是否充分比较，新增机制是否实质，检索局限是否影响结论，是否存在未复核的组合或过度声称首次。
3. **机制与反证**：前提和推理是否一致，竞争解释是否考虑，反证条件是否能推翻主假设，重大异议是否被回应而非投票压过。
4. **实验与实施**：数据、基线、对照、消融、指标、重复、不确定性与停止规则能否判别主张；实现和资源依赖是否明确；工具状态有无对应实际证据。
5. **结论与写作**：有实际结果时核对原始证据、分析程序、事前预测与事后解释；尚无结果时只审计划。检查结论是否超出任务、数据、条件或统计支持，是否把预期结果写成发现。

## 输出与验收

在当前 `proposal_review` 阶段输出 `accepted`、`checks`、`blocking_issues`。每项检查列 `check`、`evidence`、`verdict=pass|fail|unknown`，并给可操作的修订或补证据要求。通过必须有非空全部 `pass` 的检查及空阻塞列表。`pass` 的含义是“值得检验且能有效检验”，不是“已经证明有效”。

每项检查还给出 `criterion`；批准须覆盖六个规定标准，具体 ID 见运行约定。分别解释问题价值、增量、逻辑、依据、实验和实施条件，不能用一项格式检查代替完整准入审查。

按[六维评分约定](../../references/review-scoring.md)为当前全部候选及最终提案分别提供六维评分、理由和证据，并复制 `context.review_targets` 的身份与版本摘要。不能只评选中的候选，也不能把候选评分直接当作综合后提案的评分。材料不足显示“未知”；不生成加权总分、综合排名或自动通过阈值。旧请求仍按其冻结的 `output_schema` 交付。

单纯格式通过、代码可运行、全体专家同意或 LLM 高评分不支持接受。区分两类未知：

- **效果未知**（方法是否提升、机制是否如预期）：不阻塞。在 `experiment_requirements` 中写成 `kind=effect` 的必做项，给出 `question`、`decision_rule`（什么结果算支持/否定）和 `on_fail`（否定后怎么办）；该检查可判 `pass`。
- **有效性未知**（标签质量、评估泄漏、来源是否支持、统计前提）：若会让实验结果无法解释，保持 `unknown`/`fail` 并列入 `blocking_issues`；若能在主实验前用便宜的检查确认，写成 `kind=validity_gate` 的必做项（先跑检查，不通过则停止），该检查可判 `pass`。

不要把核心有效性问题写成“建议未来研究”后放行，也不要把效果未知当作阻塞。基线不被禁止，但不能被包装成创新；若提案主体是 baseline，在检查中如实指出。

批准表示值得且能够检验。已经明确的逻辑矛盾、必要材料缺失或无法判别的实验设计，应在准入检查中具体处理。评分描述六个维度，`accepted`、`checks` 和 `blocking_issues` 决定是否进入实验，高分不能抵消阻塞项。

后续结果/写作审查仅在调用方明确提供对应任务与 schema 时执行，本技能不宣称当前调度器已实现自动论文审查循环。

## 评审综合决定本身

v3 中，每个综合决定都会进入独立评审，包括"全部不选"。输出另需 `decision_assessment`：

- `synthesis_decision`：复制综合阶段的实际决定；
- `agree`：你是否同意这个决定；
- `reason`：理由。

综合决定为 `ready` 时，`accepted` 按原有准入标准判断。综合决定不是 `ready` 时，没有提案需要准入，`accepted` 必须为 `false`；你的判断写在 `decision_assessment` 中：是否确有阻塞，被放弃的候选是否被公平对待，`next_action` 是否合适。

请查看 `context.debate_ledger` 和 `context.conflict_of_interest`：未解决的阻塞异议是否被如实处理；综合者（领域专家）对自己候选的取舍是否与其他候选同一标准。

## 补证据任务（stage=evidence）

当 `request.stage` 为 `evidence` 时，只按 evidence schema 输出核查报告，不输出评审评分或准入决定。

- 回答 `context.issue` 中分配的问题，先阅读已有综合、独立评审、讨论台账及 `evidence_reports`；不要重复已经完成的检查。报告中的 `affected_idea_ids` 必须使用当前候选的真实 ID，不能填写“全部候选”等描述。
- 可以检索、读原始文献和标注、编写并执行小规模的数据统计脚本。脚本、统计输出和来源放在本任务目录，提供可追溯路径及定位。禁止训练、运行或评估候选方法，禁止访问封存最终评估数据；这些工作必须走实验入口。
- 区分已观察的事实、推断和未知。计数或抽样不能证明不存在漏标正例；资料缺失、工具失败必须如实记录，不能虚构 resolved。无法访问数据时输出限制和所需资源，不自行申请付费服务或扩大任务为完整数据工程。
- `outcome`：resolved（证据支持问题已解除）、premise_fails（证据反驳前提）、needs_experiment（需运行方法判断）、needs_human（确需外部授权/人工标注/资源）、unresolved（现有材料不能判断）。每个结果均须记录来源或失败检查记录；这只是待复核报告，不是最终裁决。
- `changes` 是受影响的前提维度，可同时包含 assumption、mechanism、data、statistical_guarantee；仅补充事实时为空。方案或协议可由专家修改时，不要仅因此填 needs_human。
- `next_step` 写清楚下一步、所需资源和能回答的问题；needs_experiment 要给出可判别的观测及允许的结论范围，不能以实验标签绕过泄漏、错误标签或不成立的统计前提。

## 收到补证据后的独立评审

`context.evidence_reports` 是有路径和摘要哈希的真实任务产物。逐项核对原质疑、作者回应、来源与结论，不能因为报告写了 resolved 就认定问题解决。候选效能尚未知可转为编号实验必做项；评价有效性缺陷不能如此放行。探索性检查必须有有效的检查协议和明确的结论边界，不能支撑未经满足前提的确认性主张。

只有影响最终选中方案或全部可行方案、且无法通过专家修改解决的外部资源缺口，才需要暂停等人处理；个别候选受阻可以搁置。没有可自动补充的材料时同意 next_action=stop，并明确人工所需事项，不反复要求 gather_materials。
