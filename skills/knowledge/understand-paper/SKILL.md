# 理解论文

按[论文理解协议](../../references/paper-understanding-protocol.md)处理实际取得的材料。先把来源与覆盖记录做准确，再判断论文究竟证明了什么；摘要、文件存在或勾选已读都不能替代这两项工作。

## 操作

1. 建立正文、附录/补充材料、图、表及可用代码的清单，固定来源版本与实际文件哈希。列出论文提及但未取得、不可读或尚未检查的材料；不因缺材料而补写原文。
2. 按章节、证明、图表与附录等有意义的单元分块完整阅读，保留范围、具体观察与缺口。跨块追踪符号、定义、前提和图文关系，回读相邻上下文；按实际覆盖标状态，不凭摘要或自动提取完成宣称读完。
3. 建立问题到章节、公式、图表、代码的检索导航，保留精确锚点与源版本。提取稿用于检索，排版、公式或视觉内容存在歧义时回到原始页面；当前项目没有自动 PDF 转换或全页审查执行器。
4. 按论文类型分析问题、贡献、机制/论证、关键条件与证据。为核心主张连接支持与反驳材料，分清作者报告、作者解释、系统推断和未知；具体检查公式与图表中的条件、单位、统计口径、对照和误差解释。
5. 分开审查材料忠实性与科学理解：先确认内容没有漏读、错位或错误转录，再检查证据是否支持主张、哪些替代解释仍成立。把缺口对后续构思或实验的影响写明；理解论文不等于运行代码或复现结果。

## 输出与交接

当 `stage=corpus` 时，这些操作用于逐篇阅读，按语料任务 schema 返回论文条目与 `idea_trace`，必要的阅读记录放在允许的条目扩展中。不要用论文专家的顶层 `knowledge` 结构替换语料产物；下面的严格知识结构用于后续 `paper` 任务。

按当前 `request.output_schema` 在 `knowledge.paper_understanding` 中记录 `paper_type`、`sources`、`coverage`、`navigation`、`analysis` 与 `limitations`，精确字段与引用语义见协议。v2 请求的已读/部分已读来源必须有真实文件路径和 SHA-256；代码目录经 `source_paths` 提交，来源条目指向其中固定文件或清单。部分阅读可保存，但不能据此晋级。

协调器负责冻结材料与生成知识导航，不自行填写 `_asset`。`knowledge/index.md` 及理解/轨迹/策略 JSON 是已提交知识的检索视图，不是自动 PDF 转换或已经理解的证明；按需读取，仍以真实来源为依据。

把有来源的理解交给 [trace-paper-ideas](../trace-paper-ideas/SKILL.md) 建立论证轨迹，再交给 [distill-reasoning-patterns](../distill-reasoning-patterns/SKILL.md) 提炼迁移策略；本步骤不以作者未披露的发现过程填补逻辑缺口。后续 [verify-expert](../verify-expert/SKILL.md) 核查知识资产；没有真实问答记录时，不宣称专家的交互理解能力已通过独立测评。
