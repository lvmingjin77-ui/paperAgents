# 验证专家知识资产

当前 `expert_review` 是对可复用知识包和已有能力证据的独立审查，调度器不会另行调用被审查专家回答验收题。采用[证据规则](../../references/evidence-policy.md)、[专家生命周期](../../references/expert-lifecycle.md)和[运行约定](../../references/runtime-contract.md)。

## 操作

1. 先定义这次需要专家承担的实际任务，区分知识解释、机制迁移、方法调用与结果复现。各项分别验收，不用一个笼统能力分数代替。
2. 从原始来源挑选关键主张和构建摘要未直接覆盖的片段，检查事实、公式、适用条件、负面证据与锚点。领域专家还需检查跨论文分歧和覆盖缺口。
3. 检查知识包能否支持设计与替代方案的区别、不适用场景、原文未回答的问题及无依据因果推断的辨认。可以列出后续验收题与有来源的期待条件，但这些是测试设计，不是已观察到的专家回答。只有输入含真实答题记录时，才记录并评价该回答；不得替被审查专家生成答案再据此宣布其通过。
4. 检查研究轨迹是否把推断冒充作者思路；检查工具状态是否有匹配的实现、日志和结果，必要时转给方法工具验证。来源核对不能替代实际运行。
   对 v2 论文知识，按[论文理解协议](../../references/paper-understanding-protocol.md)分别核对材料覆盖与理解：抽查关键公式的符号/条件、图表的分母/单位/误差含义、附录是否限制正文主张，并检查七类分析中的 unknown 是否影响当前能力。`coverage=complete` 仅是申报材料阅读状态，不能代替理解审查。
   按[论证图协议](../../references/reasoning-trace-protocol.md)检查关键依赖边：前提是否真支持后继步骤，观察是否被写成因果机制，缺失消融是否被补成已做实验。结构无环并不说明推导正确。
   按[策略协议](../../references/reasoning-patterns-protocol.md)检查策略能否说明具体变换、适用条件和失效例子；尝试构造符合表面类比却破坏关键前提的场景，检查策略是否会拒绝错误迁移。这里记录的是审查者对资产的检查，不伪造被审专家的答题表现。构建时的策略迁移状态保持 `unvalidated`。
5. 针对核心失败要求局部修订后重验，并保留原失败记录。非关键未知应显式限定能力范围；若当前任务依赖该未知，不能批准该能力。

产物含 `knowledge.communication_analysis` 时，按[表达分析协议](../../references/paper-communication-protocol.md)抽查章节/图表的真实功能、引用锚点及迁移边界，不把叙事推成发现历史。含 `knowledge.reuse_assessment` 时，按[复用协议](../../references/expert-reuse-protocol.md)核对来源版本、保留内容和能力降级；旧审查或旧运行不能冒充当前版本已验收。这些可选扩展尚无专用 schema 校验，必须检查原始依据。

## 输出与验收

按审查 schema 输出 `expert_id`、`accepted`、`checks` 与 `limitations`，每项检查为 `check`、`evidence`、`verdict=pass|fail|unknown`。证据写明本次检查范围、来源、实际观察和判定理由，不能只有“另一 agent 认为正确”。资产审查通过不证明未测试的答题、迁移或执行能力；在 `limitations` 保留这个边界。

检查附 `criterion`；批准须分别覆盖材料忠实性、科学理解、论证与迁移、能力证据四项，字段 ID 见运行约定。能力证据按实际声明核查；未声明可执行能力的论文不需要伪造运行，但必须准确限定能力。

只有检查非空且全部通过时才 `accepted=true`。缺少材料或未运行写 `unknown`；不得为了推进流程把未知改成通过。若产物结构无法容纳局部修订建议，将它们写入对应检查的证据说明。
